# 移行版の検証記録

実施日：2026-10-25。環境：Windows、Node.js、Playwright 1.64.1、ChromiumとWebKit。

結果：静的・保全・公開範囲の5テストが成功。ブラウザは11シナリオ×2エンジンの22ケースを確認し、初回20件成功、期待値修正後に残り2件の再実行が成功しました。

## 検証対象

- 原本のSHA256、Gitタグからの復旧内容との一致。
- 元のCSS・3つのJSブロックのバイト一致、HTMLの実行順、JS構文。
- 個人データが既定でGit除外となること、公開用6ファイルの許可リスト。
- すべての既存パネルの初期表示、初期表示時の不要な外部通信がないこと。
- 合成画像・CSV・固定推論結果での解析UI、448px/BGR用テンソル作成、セッション再利用。
- 新規教師JSONが同じ入力のv18原本と一致すること。
- 正しい／間違い／未確認／不要、学習承認、未判定手動追加の除外。
- 既存JSONの通常保存でreview・training_labels・未知の独自項目・旧スキーマ・項目欠落が保全されること。
- 再生成チェックによる更新、別途の学習用承認、元オブジェクトの不変性。
- 画像ID不一致の拒否、画像変更・JSON再読込で再生成チェックが解除されること。
- 実際のブラウザダウンロードイベントから教師JSON・辞書・衣装・学習データセットを読み戻すこと。
- 辞書の取込・手動編集・保存・再読込、英語タグIDの維持。
- 衣装の取込・重複防止・出力・再読込。
- 複数JSON管理・学習承認済みデータ抽出・不整合拒否・履歴表示。
- 翻訳許可前に送信せず、許可後はタグ文字列を送ること（API応答は模擬）。
- 390px幅で横にはみ出さず、4つの判定を選択できること。

## 明確な検証限界

- ONNX Runtimeとモデル推論は固定結果に差し替えたテストです。467MBのモデル、実際の解析精度、所要時間、最大メモリ使用量は未検証です。
- WebKitテストはWindows上で実行しており、iPhone Safariの実機テストではありません。
- 既存の個人用JSON・辞書・衣装ファイルは未提供です。テストは架空の値だけを使っています。
- MyMemory実通信、翻訳失敗2件の原因、jsDelivrからのエンジン取得は未検証です。
- クリップボードのOS権限、iCloud Driveへの保存、ページ終了警告のiOSでの挙動は未検証です。
- GitHub Pagesへの公開・CORS・オフライン動作は未実施です。

## v18から引き継いでいる既知の課題

今回の互換移行では、JSON保護以外の動作変更を混ぜていません。

- 翻訳失敗理由が表示されず、繰り返し失敗したタグが再試行対象に残る。
- 辞書出力の同名キーではオンラインキャッシュが手動訳を上書きする可能性がある。
- 一括翻訳の母集団がCSV全タグではない。
- 履歴集計は表示説明と異なり、学習未承認の判定も集計する。
- 複数JSON一覧では「不要」が未確認に数えられる。
- `tag_review.excluded` のみを持つ旧形式の復元が不十分。
- 衣装の直接編集、途中作業の自動保存・再開、モデル自動取得は未実装。
- 既存JSONの編集には再解析が必要で、35%以上のタグが0件だと教師JSONを生成できない。

初回のブラウザテストで履歴の表示訳を「ロングヘア」と仮定して2件失敗しました。実際のv18はルール訳「長い髪」を優先するため、既存動作に合わせてテストの期待値を修正しました。アプリの翻訳ロジックは変更していません。

## 次の検証とiPhone実機確認

まず既存ファイルのコピーで往復確認し、次にPCの本物のモデル推論を確認します。公開後のiPhone確認は一度に全部を依頼せず、最初は以下の手順から案内します。

1. 提供するHTTPS公開URLをSafariで開く。
2. 指定したモデル・CSVを選択し、個人情報を含まないテスト画像を1枚選ぶ。
3. 「解析を開始」を押し、画面を開いたまま待つ。
4. 解析完了までの時間、最後のログ、Safariが再読み込みされたかを報告する。

この確認が通ってから、タグ判定・教師JSONの「ファイル」への保存・辞書と衣装の移行へ進みます。現時点ではiPhoneの操作は不要です。
