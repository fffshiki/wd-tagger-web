# 互換性とデータ更新の契約

## 教師JSON

新規作成はv18の最終出力と同じ `schema_version: "1.2"` と `_教師データ_v10.json` を使用します。英語タグIDを日本語へ置換しません。未確認・不要・未判定の手動追加を `training_labels` に含めません。

既存JSONの操作は次の契約に従います。

| 操作 | review / training_labels | その他 |
| --- | --- | --- |
| 読み込み・表示・判定UI変更 | 元オブジェクトを変更しない | ファイルへ書き込まない |
| 通常のJSON保存・コピー | 値・独自項目・項目の欠落を保持 | ai_predictionのみ今回の解析・判定提案へ更新 |
| 専用の再生成チェックを付けて保存・コピー | 今回の判定から再生成 | schema_versionを1.2、excluded_tagsを今回値へ更新。それ以外の既存トップレベル項目を保持 |

再生成を選んでも、学習用承認がない場合は `training_labels.status = not_approved`、学習用の正例・負例は空です。学習用承認には編集確認と1件以上の正しい／間違い判定が必要です。再生成チェックは別のJSON読み込みや画像変更時に解除します。

既存の `confirmed_tags`・`rejected_tags` は再生成時も保全します。旧項目と新しい `training_labels` の役割を混同せず、学習承認の判断は `training_labels` と `review` によります。新規のv18互換出力では、手動追加が `confirmed_tags` に入る場合がありますが、学習用には承認されません。

通常保存で新しいAI予測と従来の学習タグが食い違う場合、v18のデータセット作成は不整合として除外することがあります。既存学習情報を黙って上書きすることで解消しません。確認後に明示的な再生成を選びます。

v18はJSON再編集にも画像の選択と解析を要求します。この段階ではその流れを維持しています。実際の過去バージョンのJSONは未提供のため、合成した1.0／1.2形式に対する確認です。

## 辞書・衣装

- 辞書：`{format: "wdtagger_japanese_dictionary", version: 1, translations: {...}}`
- 衣装：`{format: "wdtagger_outfit_presets", version: 1, outfits: [...]}`
- localStorageキーはv18と同じ3種類を使用します。
  - `wdtagger_custom_jp_dictionary_v15`
  - `wdtagger_v17_online_translations`
  - `wdtagger_outfits_v16`

HTMLを開いていた環境と新しいURLは保存領域が異なります。元のアプリから辞書・衣装をJSONで保存し、新しいURLで読み込みます。個人辞書をアプリのソースへ埋め込みません。

衣装の取込時に内部idを再発行するv18の仕様を維持しています。series・character・description・source_tag・image_id・image_filename・created_atを引き継ぎます。同一series＋characterは重複とみなします。

## 全CSVタグの翻訳管理に向けた設計（追加実装は次段階）

1. 推論結果 `lastTags` とタグ全体 `tagRows` を別に維持する。全タグ管理の母集団はCSVの全行であり、現在の予測や手動辞書のキーで絞らない。
2. モデルとCSVのリビジョン・ハッシュ・CSVの行順を記録する。推論スコアは行番号へ対応するので、表示用ソートで元の行順を変更しない。
3. 正式タグIDに、表示用翻訳と状態（未翻訳・自動訳・手動確認・要確認・失敗）を関連付ける。日本語があることだけを正訳の根拠にしない。固有名詞を原語で使う判断も記録する。
4. 手動確定訳を優先し、専門辞書・標準訳・オンライン候補を分ける。オンライン翻訳で手動確定訳を置換しない。
5. 翻訳失敗はタグID・理由・HTTP/API状態・試行日時を別ストアへ記録する。ブラウザが詳細を開示しないCORS/通信失敗は断定しない。タイムアウト・再試行・中断に対応する。
6. CSVにない既存辞書キーも残す。別モデルや旧データのキーを自動削除しない。
7. 従来の辞書エクスポート `translations` を維持する。管理用メタデータは別のバージョン付きバックアップに格納し、教師JSONのスキーマへ混ぜない。
8. 一覧は検索・ページ分割で1万件超を扱う。オンライン処理は明示的に許可したタグ文字列だけを送る。

この段階では全タグ翻訳UI、IndexedDB、モデル自動取得、翻訳エラー記録は未実装です。先にv18互換移行を検証する順序を守ります。
