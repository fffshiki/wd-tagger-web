# 互換性とデータ更新の契約

## 教師JSON

新規作成はv18の最終出力と同じ `schema_version: "1.2"` と `_教師データ_v10.json` を使用します。英語タグIDを日本語へ置換しません。未確認・不要・未判定の手動追加を `training_labels` に含めません。

既存JSONの操作は次の契約に従います。

| 操作 | review / training_labels | その他 |
| --- | --- | --- |
| 読み込み・表示・判定UI変更 | 元オブジェクトを変更しない | ファイルへ書き込まない |
| 未編集の通常保存・コピー | 値・独自項目・項目の欠落を保持 | ai_predictionを含め、全項目・配列順を保持 |
| 判定・項目を編集した通常保存・コピー | 元の値を保持 | ai_prediction内の編集した提案を更新。新しく推論した場合だけraw_predictionsを更新 |
| 専用の再生成チェックを付けて保存・コピー | 今回の判定から再生成 | schema_versionを1.2、excluded_tagsを今回値へ更新。それ以外の既存トップレベル項目を保持 |

再生成を選んでも、学習用承認がない場合は `training_labels.status = not_approved`、学習用の正例・負例は空です。学習用承認には編集確認と1件以上の正しい／間違い判定が必要です。再生成チェックは別のJSON読み込みや画像変更時に解除します。

既存の `confirmed_tags`・`rejected_tags` は再生成時も保全します。旧項目と新しい `training_labels` の役割を混同せず、学習承認の判断は `training_labels` と `review` によります。新規のv18互換出力では、手動追加が `confirmed_tags` に入る場合がありますが、学習用には承認されません。

通常保存で新しいAI予測と従来の学習タグが食い違う場合、v18のデータセット作成は不整合として除外することがあります。既存学習情報を黙って上書きすることで解消しません。確認後に明示的な再生成を選びます。

既存JSONは、画像やモデルなしで読み込んで保存できます。保存済みのraw_predictions・review_states・判定リストから表示用のタグ一覧を構成し、低スコアの保存済みタグも表示します。読み込み時に推論を実行しません。

判定復元は、同名・同カテゴリーのreview_states、ai_prediction.tag_review、トップレベルreviewの判定リストの順に参照します。旧形式のexcludedも復元します。相反する判定は未確認として表示し、元の値は保持します。confirmed_tagsだけの古いデータは自動候補が混在する可能性があるため、正しい判定や学習承認へ自動昇格させません。

画面上では保存済みの承認状態を独立して表示します。trainingApproveチェックは「今回の再生成」に対する承認操作であり、未チェックでも保存済みの承認状態を解除しません。再生成を選んだ場合だけ、このチェックが新しい出力へ反映されます。

実データの検証ファイルとその派生コピーはGit管理外に置きます。公開用の回帰テストには独立した架空データだけを使用します。全ての過去バージョンの実データを確認したという意味ではありません。

## 辞書・衣装

- 辞書：`{format: "wdtagger_japanese_dictionary", version: 1, translations: {...}}`
- 衣装：`{format: "wdtagger_outfit_presets", version: 1, outfits: [...]}`
- データ本体にはv18と同じlocalStorageキーを使用します。
  - `wdtagger_custom_jp_dictionary_v15`
  - `wdtagger_v17_online_translations`
  - `wdtagger_outfits_v16`

HTMLを開いていた環境と新しいURLは保存領域が異なります。元のアプリから辞書・衣装をJSONで保存し、新しいURLで読み込みます。個人辞書をアプリのソースへ埋め込みません。

辞書の取り込みは従来どおり併合し、同じ英語タグIDは読み込んだ値に置き換えます。文字列をtrim・短縮せず、空文字や長い訳も保持します。不正な値を含むファイルは一部だけ取り込まず、全体を拒否します。書き出し時は登録済みの値が同名キャッシュより優先し、キャッシュは未登録キーだけを補います。空の保存領域で取り込んだファイルは、未編集・キャッシュ未追加なら全項目が一致する出力になります。

MyMemoryの通信先、許可チェック、最大30件という仕様は維持しています。応答待ちに辞書が編集された場合、古い応答でその編集を削除・上書きしません。翻訳エンジンの置き換えや本格的なエラー管理は行っていません。

翻訳表示は、利用可能な登録値→キャッシュ→端末内ルール→個人辞書とは独立した内蔵辞書→原語の順です。手動の日本語訳を優先し、暫定値で内蔵辞書が遮られないようにしています。内蔵訳で表示できても、元の暫定登録を削除したり、手動確認済みに昇格させたりしません。

英字のみの候補は一律採用せず、virtual_youtuber=VTuber、bdsm=BDSM、science_fiction=SFの組み合わせだけをadopted_latinとして受け入れます。これは候補の許可で、未登録キーの作成ではありません。例えばbdsm=bdsmやsynthetic_tag=SFを採用済みとは扱いません。日本語の手動修正があれば、それがこれらの候補より優先します。他の略語の追加は別途確認します。

adopted_latinと翻訳の取得元は表示判定用の内部情報です。辞書v1、教師JSON1.2、衣装v1へ項目を追加しません。採用済み略語と手動の学習承認は別物であり、翻訳状態からタグの正誤判定を自動変更しません。

辞書の取込、手動編集、標準訳へ戻す操作、オンライン結果の反映時は、既存履歴テーブルのタグ名セルも更新します。行の順序、集計値、タグID、現在の編集・判定状態は維持します。

衣装はID、追加項目、項目の欠落、値の型、登録順を保持します。同じシリーズ・人物でも内容やIDが異なる登録は、読み込み時にまとめて削除しません。完全一致の再取り込みは件数を増やさず、入力に同じ登録が複数含まれる場合はその個数も保持します。同じ既存IDに異なる内容を併合しようとすると、全体を拒否します。新規の手動登録は従来どおりシリーズ・人物の重複を防ぎます。

追加のトップレベル項目を保持するため、辞書と衣装それぞれの付加情報だけを別のlocalStorageキー（wdtagger_dictionary_envelope_v1、wdtagger_outfit_envelope_v1）へ保存します。書き出すファイルのformat・version・基本構造は変更しません。既存付加情報と矛盾する別ファイルの併合は拒否し、黙って置き換えません。

UTF-8として読めないファイルは理由を表示して拒否します。破損した先頭などを推測で補修して取り込むことはしません。

## 全CSVタグの翻訳管理に向けた設計（追加実装は次段階）

1. 推論結果 `lastTags` とタグ全体 `tagRows` を別に維持する。全タグ管理の母集団はCSVの全行であり、現在の予測や手動辞書のキーで絞らない。
2. モデルとCSVのリビジョン・ハッシュ・CSVの行順を記録する。推論スコアは行番号へ対応するので、表示用ソートで元の行順を変更しない。
3. 正式タグIDに、表示用翻訳と状態（未翻訳・自動訳・手動確認・要確認・失敗）を関連付ける。日本語があることだけを正訳の根拠にしない。固有名詞を原語で使う判断も記録する。
4. 手動確定訳を優先し、専門辞書・標準訳・オンライン候補を分ける。オンライン翻訳で手動確定訳を置換しない。
5. 翻訳失敗はタグID・理由・HTTP/API状態・試行日時を別ストアへ記録する。ブラウザが詳細を開示しないCORS/通信失敗は断定しない。タイムアウト・再試行・中断に対応する。
6. CSVにない既存辞書キーも残す。別モデルや旧データのキーを自動削除しない。
7. 従来の辞書エクスポート `translations` を維持する。管理用メタデータは別のバージョン付きバックアップに格納し、教師JSONのスキーマへ混ぜない。
8. 一覧は検索・ページ分割で1万件超を扱う。オンライン処理は明示的に許可したタグ文字列だけを送る。

全CSV行を対象にする検証用関数getTranslationCatalogを用意し、推論結果・登録辞書のキーだけに対象を限定しないことをテストしました。元のCSV順・英語ID・カテゴリーを保持します。状態は未翻訳・暫定訳・日本語あり・要確認で、日本語があるだけでは正しい翻訳や人手確認済みと断定しません。登録値の状態と、標準訳などを適用した表示値の状態を分けます。

この段階では全タグ翻訳UI、IndexedDB、モデル自動取得、翻訳エラー記録は未実装です。全件対象化の単体テストは大量の架空CSVで実施しています。公開準備では別途、公式の固定CSV10,861件を取得し、実モデルの出力数と一致することを確認しました。
