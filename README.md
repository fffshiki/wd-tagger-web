## 全タグの翻訳状況（第2-①段階）

②でCSVを選択すると、その直下に全タグ一覧と集計を表示します。初期表示は「原語表示が残る（暫定を含む）」です。⑧で辞書を読み込むと再集計します。日本語訳あり・採用済み略語・暫定訳・未翻訳を分類し、英語／日本語検索、分類・状態・出典の絞り込み、50件ごとのページ表示を行います。画像解析なしで利用できます。

「日本語訳あり」は人が確認済みという意味ではありません。辞書の暫定登録に有効な内蔵訳がある場合は、日本語表示として数え、辞書登録状態も別に表示します。一覧そのものは辞書や学習情報を変更しません。記号・数字の抽出も自動承認はしません。

## 翻訳候補の作業データ（第2-②段階）

一覧の「候補を編集」から候補を入力します。編集はIndexedDBに自動保存し、状態を未確認に戻します。未確認・採用・保留・却下の状態と履歴を管理し、表示中の候補だけを選択して一括操作できます。採用しただけでは表示訳や辞書は変わりません。原語・記号・正式略語は専用の表示方針を選びます。

「採用候補の辞書反映を確認」で差分を確認し、「既存辞書のバックアップを保存」して保存確認のチェックを入れると、辞書へ反映できます。既存の有効な登録訳は保護して除外します。候補の保留・却下・削除は、既に反映した辞書を取り消しません。反映後は従来の辞書JSONも保存してください。

「翻訳作業JSON」は `wdtagger_translation_workspace` version 1の別形式で、候補・状態・履歴・原語反映記録を保存します。復元は内容確認後に現在の作業データを置き換えます。原語採用の情報を他の端末に移すには、辞書JSONと翻訳作業JSONの両方を保存・読み込みしてください。旧アプリだけでは追加した原語採用情報を復元できません。

端末保存の失敗は警告し、入力中の候補を含めたJSON退避も可能です。「自動保存済み」を確認してから閉じてください。端末の保存領域の消去や保存中の強制終了まで保証するものではないため、ファイルへのバックアップを併用します。候補生成AI・大量自動翻訳・完全オフライン配信は未実装です。

第2-②段階追加前の安定版は、`git archive --format=zip --output=stage2a-recovery.zip translation-catalog-stage2a` で5c099deのソースを取り出せます。

安定版へ戻す場合は、`git archive --format=zip --output=stage1-recovery.zip translation-display-stage1` で1d2ca3aのソース一式を取り出せます。

## 起動

このREADMEがあるフォルダで実行します。Node.jsが必要です。

```powershell
npm.cmd start
```

表示された `http://127.0.0.1:4173/` をPCのブラウザで開いてください。サーバーはローカルPCからだけアクセスできます。iPhone用の公開URLではありません。終了はターミナルのCtrl+Cです。

画面にある公式ダウンロードリンクからモデル・CSVを保存し、従来どおりモデル・CSV・画像を選びます。推論エンジンはこのサイトのvendor/onnxruntime/から読み込み、JS・MJS・WASMを同じ1.20.1に固定します。467MBの実モデルによるPCのChromium・WebKitでの解析を確認済みです。iPhone実機は公開後に検証します。

## 既存JSONを開いたとき

JSONだけで保存済みの判定と学習承認状態を表示できます。画像・モデル・CSVの選択や再解析は不要です。

未編集の通常保存では `ai_prediction` を含めた全項目を保持します。項目の欠落、独自項目、旧 `schema_version`、配列順も保持します。判定や項目を編集した場合だけ `ai_prediction` 内の該当する提案を更新し、元の `review`・`training_labels` は保持します。JSONの空白・改行は保存時に整形されます。

既存の学習情報を更新したい場合のみ「今回の判定で既存JSONのreview・training_labelsを再生成する」をチェックします。学習ラベルの出力にはさらに「編集内容を確認済みとして保存」と「判定済みタグだけを学習用に承認」の両方が必要です。

再生成の条件と互換性上の注意は `docs/COMPATIBILITY.md` を参照してください。読み込み・表示・JSON生成のどの処理も、読み込んだ元オブジェクトや元ファイルを変更しません。

## テストと公開用ファイル

```powershell
npm.cmd ci
npx.cmd playwright install chromium webkit
npm.cmd test
npm.cmd run build
npm.cmd run audit:release
```

`dist/` の13ファイルだけをGitHub Pagesの公開成果物として使用します。モデル、ユーザー画像、教師JSON、個人辞書、衣装プリセット、baseline、テスト、node_modulesは入りません。`dist/` に想定外のファイルがあればビルドは中断します。必要なランタイム3ファイルだけはnode_modulesからビルド時にコピーします。

公開手順はdocs/PUBLISHING.mdにあります。Pushではデプロイされず、確認後にGitHub上で手動実行する方式です。

`.gitignore` は既定でファイルを除外し、アプリソースとテストだけを明示的に許可しています。ただし `git add -f` で除外を回避したり、許可済みソースへ個人データを埋め込んだりしないでください。公開前にも追跡ファイルを確認します。
